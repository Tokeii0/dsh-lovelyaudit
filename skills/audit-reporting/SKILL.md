# 审计交付与定级规范

**报告是审计的唯一交付物。** 挖到 Critical 但写不清楚、定级不实、缺证据，等于没挖到——运维一测复现不了，整份报告的信任度归零。

## R1 定级：先给 P5 语义级，再给 CVSS

**两套等级各有用途，都要给：**

| P5 语义级 | 含义 | 对运维的意思 |
|---|---|---|
| `unauth` 未授权成立 | 无需任何凭据即可触发 | **立刻修** |
| `session` 需会话 | 任意登录账号可触发 | 看注册是否开放——**开放注册 ≈ 未授权** |
| `key` 密钥门 | 缺一把钥匙（密钥/token/内网位置） | 写清钥匙在哪、怎么会泄露、拿到后影响多大 |
| `blocked` 本实例被挡 | 缺陷真实，当前边界不可达 | 纵深防御依据，**换实例可能成立，不能不报** |
| `code` 代码缺陷 | 未实机复现 | 诚实标注，别吹 |

CVSS 3.1 向量按**实测**填，不要按想象填：

```
AV(攻击途径) N网络/A邻接/L本地   AC(复杂度) L低/H高
PR(所需权限) N无/L低/H高          UI(用户交互) N无/R需要
S(范围)      U不变/C改变（能影响到本组件之外，如容器逃逸/云账户）
C/I/A(机密性/完整性/可用性) H高/L低/N无
```

**映射纪律**：`unauth` → `PR:N`；`session` → `PR:L`；仅管理员可触发 → `PR:H`（**大多不该报 High**）。存储型 XSS → `UI:R` + `S:C`。SSRF 拿到云凭据 → `S:C` 且 C/I/A 全 H。

**级别通胀是报告最常见的病**：
- 需要管理员权限的"任意文件上传" ≠ Critical。
- 无法证明可达的代码缺陷 ≠ High。
- 缺少 CSP / 缺少安全响应头 ≠ 漏洞，是**加固建议**，单列一节，不要混进漏洞计数。
- 反过来也别缩水：跨租户数据读取、未授权改密、密钥泄露即接管——这些就是 Critical。

## R3 单条报告的最小要素（缺一不可）

每个漏洞**独立成篇**，绝不合并（合并会让运维无法分派与验收）：

```
1  编号与标题        SRC-07 用户导出接口未校验资源归属导致任意用户数据泄露
                    （标题写「哪个位置 + 什么缺陷 + 什么后果」，不写「存在越权漏洞」这种空话）
2  等级             Critical / High / Medium / Low  +  CVSS 3.1 向量与分数
3  P5 语义级         unauth / session / key / blocked / code
4  分类编号          CWE-639 · OWASP A01 · API1
5  影响面            受影响实例（哪几个 URL/端口）、受影响数据量级、最坏后果
6  漏洞位置          文件:行（白盒）+ URL/参数（黑盒），两者都给
7  代码片段          最小可读片段，标出 Source 与 Sink，**不要贴整个文件**
8  成因（三点闭合）   ① 为什么是缺陷 ② 入口线上可达性 ③ 证据
9  复现步骤          可直接复制的最小请求（curl / HTTP 原文），含前置条件（是否需登录、哪个账号）
10 证据             原始请求 + 原始响应（脱敏后）+ 时间戳；差分类给对照组两条
11 修复建议          临时缓解 + 根治方案 + 代码示例
12 变体清单          同一模式在项目中的其他位置（见 R6）
```

## R4 证据规范

- **原始请求 + 原始响应**成对出现。只有响应没有请求 = 不可复现。
- **差分类漏洞必须给对照组**：布尔盲注给 `1=1` 与 `1=2` 两条；IP 白名单绕过给「不带头」与「带头」两条；越权给「A 的会话取 A」与「A 的会话取 B」两条。**单条响应证明不了差分。**
- **时延类**给多次测量（避免网络抖动误判），写清基线时延。
- **带外类**给 DNSLog/Collaborator 的命中记录与时间戳。
- 加**时间戳**与**探测来源 IP**——便于对方从日志侧核对，也是审计合规要求。
- PoC 用**最小非破坏**动作（差分 > 时延 > 只读回显）。写 EXP 时标注「仅用于授权复现，勿在生产执行」。

## R5 PII 与敏感数据处置（红线）

- **证明即止**：证明能读，不要拖库。任意文件读证到 `web.xml`/配置即可，不去读用户表。
- **报告内脱敏**：手机号 `138****5678`、身份证保留首尾、口令一律 `******`、token 截断。**报告本身会被转发、会进邮件、会存网盘——它是新的泄露面。**
- 截图打码；不要把真实用户数据当"证据"整表粘贴，给**行数统计**代替内容（"可读取 12,483 条用户记录，示例字段：姓名/手机/住址，已脱敏"）。
- 拿到的凭据/密钥：报告里标注位置与类型，**不写完整值**；单独通过安全渠道给对方。
- 审计过程中导出的任何数据，交付后销毁并在报告中声明。

## R6 修复建议的质量标准

一条合格的修复建议有三层：

1. **临时缓解**（今天就能上）：WAF 规则、关闭端点、加访问控制、限制来源 IP。写清**这只是缓解，不是修复**。
2. **根治**：改代码的具体做法 + 代码示例。
   - 不要写"请对输入做过滤"这种废话。写「用 `PreparedStatement` 参数绑定；`order by` 的列名走白名单映射」。
   - 给出**正确的**代码片段，不只是描述。
3. **变体清单**：`unknown-vuln` 技术七的产物。「同样的模式还出现在 A.java:88、B.java:210、C.php:45」——**只修报告里那一处，等于没修**。这一条最能体现审计深度，也最容易被省略。

再加一层**根因**：如果 5 个漏洞都源于「鉴权 Filter 的 url-pattern 漏了 `*.do`」，就要在报告里单列一条**根因项**，修根因一次解决 5 条。

## R7 修复路线图排序

按 `已验证 × 影响面 × 修复成本` 排，给对方一张可执行的表：

| 优先级 | 条件 |
|---|---|
| P0 立刻（24h） | `unauth` 且 Critical：未授权 RCE、未授权全量数据泄露、未授权接管 |
| P1 一周 | `session`/`key` 的 Critical/High；已验证的越权与跨租户 |
| P2 一月 | Medium；`blocked`（换实例即成立的，要说明"当前靠边界挡着，边界一变就成立"） |
| P3 排期 | Low、加固建议、依赖升级 |

## R8 复测

- 每条漏洞给**复测方法**（就是 R3 第 9 项的复现步骤，可直接重跑）。
- 复测三种结论：`已修复` / `未修复` / `修复不彻底（绕过成立）`——**第三种最常见**：只补了黑名单、只修了报告里那一处、只改了前端。
- 复测要**重跑变体清单**，不只跑原始 PoC。
- 修复引入新问题也要报（如为修穿越加了 `replace("../","")` → `....//` 绕过）。

## R9 报告常见坑（自查）

- [ ] 把白盒结论直接写成黑盒结论（"未授权注入"其实需要登录）——**信任崩塌头号原因**
- [ ] 级别通胀 / 把加固建议混进漏洞计数
- [ ] 没有变体清单，只报单点
- [ ] 没有根因项，5 条漏洞让人改 5 次
- [ ] 证据缺对照组，运维复现不出
- [ ] PoC 是破坏性的，运维不敢跑
- [ ] 报告里明文躺着真实用户数据和密钥
- [ ] 多实例只报了一个实例，另一个实例的结论没写（同缺陷不同边界 → 不同结论，都要写）
- [ ] `blocked` 的缺陷被丢掉没报（它们是纵深防御依据，也是边界变更时的定时炸弹）
- [ ] 模板化套话（"建议加强安全意识"），没有可执行动作

## R10 与 workspace 的衔接（R3 的 12 项分别存哪个字段）

`audit_workspace` 的 finding 字段是**固定集合**（schema 严格，传别的字段会报错）。R3 各项对应：

| R3 要素 | 字段 |
|---|---|
| 编号 / 标题 | `code` / `title` |
| 等级 | `severity`（Critical/High/Medium/Low/Info）+ `cvss`（向量串） |
| P5 语义级 | `grade`（unauth/session/key/blocked/code） |
| 分类编号 | `cwe` / `owasp` |
| 影响面 | `impact` |
| 位置 | `location`（文件:行 + URL/参数） |
| 代码片段 | `snippet` |
| 成因三点闭合 | `rationale`（为什么是缺陷）/ `reachable`（可达性）/ `evidence`（证据）——**三者缺一，`verifyStatus` 会被自动打回 draft** |
| 触发前置 | `prerequisite`；污点两端用 `source` / `sink` |
| 复现步骤与 PoC | `verifyMethod` / `verifyResult` / `poc` / `exp` |
| 修复建议 | `fix`（三层：缓解 + 根治 + 代码示例） |
| **变体清单** | `variants`——同模式的其它位置；**没做变体分析就如实留空，不要编** |
| **根因** | `rootCause`——多条漏洞同源时填，修一次解决一片 |

- 三点闭合后系统自动派撰写子代理产出**该条**的独立报告，不要等到 P7、不要多条合并。
- P7 覆盖矩阵、§H 矩阵外清单与「已查·无」的阴性结论一并交付——**证明审全了，和证明有洞同样重要**。
