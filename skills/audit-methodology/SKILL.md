# 审计总体思路（P0–P7 螺旋）

先建威胁模型再动手：**谁会打**（未授权外部 / 低权限内部账号 / 中间人）、**想要什么**（数据 / 权限 / 立足点）、**系统最怕什么**（① 未授权 RCE：上传/反序列化 ② 未授权数据泄露：任意文件读/SQLi/越权 ③ 账号接管：认证绕过）。威胁模型决定所有动作的优先级——看到工资/病历模块，第一反应应是「泄露 = 全员数据曝光，优先级拉满」。

螺旋节奏，不是直线流水线：

```
P1指纹 → P2测绘 → P3黑盒摸底 → P4白盒深挖 → P5互证 → P6验证
       ↑ 发现新实例 / 新边界 / 新入口后回炉
P7 覆盖矩阵收口
```

审计不是一遍过的流水线，是「黑盒发现→白盒解释→黑盒验证→发现新面」的螺旋。每次互证都可能暴露新攻击面，回炉再审，直到覆盖矩阵没有空格才算闭环。

## P0 交战规则与目标确认

钉死「能做什么、不能做什么、打哪些目标」：

1. **确认授权范围**：哪些 IP/域名/端口在授权内。书面授权是前提。
2. **划红线**（尤其生产）：
   - ✅ 允许：只读探测、响应差分、时延、字节码分析、读无害文件（web.xml 等配置）。
   - ⚠️ 灰区：任意文件**读**（节制隐私）、注入盲态探测（短 sleep）。原则：**能用差分/时延证明的，就不落地真实利用**。
   - ❌ 禁止：写/删数据、真传 WebShell、爆破口令、DoS、`--os-shell` / `--dump`。
   - 红线以用户 P0 填写为准；用户没填，不要自行发明默认禁令。
3. **建目标台账**：不止一个 URL——把所有相关**端口和实例**列进来。**同一应用常有多个部署实例（主/移动/门户/测试/灾备），边界防护未必一致；一个实例打不通，换一个可能就通了。台账必须穷举所有实例。**

产出：目标/实例台账（用途、是否生产、边界防护线索）、红线清单。

## P1 信息收集与指纹

指纹越准，越能借力已知漏洞。

1. **HTTP 指纹**：Server、Set-Cookie 名、X-Powered-By、首页跳转、错误页特征、favicon hash。
2. **产品识别**：Cookie 名、路径特征、登录页版权、JS/CSS 路径 → 锁定产品。
3. **版本/构建时间**：文件时间戳、jar 版本、.class 编译信息、页面注释。
4. **已知 CVE 拉取**：确认产品后立刻把该产品线的公开漏洞拉进候选池，并列出该产品线的**标准攻击面端点**——**即使源码没给，也要主动去线上验证它们是否存在**。
5. **枚举实例**：配置、日志、页面里挖其他 IP/端口/域名。

常见漏点：只盯给的源码，不验证「应该存在但没给源码」的组件 → 漏掉产品级已知洞。指纹的价值就是提醒「这类产品还有哪些标准攻击面」。

产出：指纹表、产品/版本、已知 CVE 候选池、实例清单。

## P2 攻击面测绘（"不放过"的第一道兜底）

**把地图画完再打。** 五张清单，缺一不可：

1. **路由清单**：web.xml 每个 servlet-mapping / filter-mapping / welcome-file / error-page；框架注解路由全量提取（如 `grep -r "@RequestMapping"`）；URL 重写规则。
2. **JSP/页面清单**：全量枚举——每个都是潜在直连入口。
3. **内置/第三方组件端点**：编辑器（UEditor/FCKeditor）、报表、上传组件，各自带一堆端点。
4. **静态与残留**：.bak/.rar/.zip/.svn/.git/副本/test*——源码泄露与备份。
5. **Source/Sink 台账**：粗扫所有输入源和危险汇聚点建索引，为 P4 打底。

常见漏点：

- 只审业务大接口，漏边角：验证码 servlet、代理 servlet、include 片段、上传子组件——往往正是这些「不起眼」的地方无鉴权。
- **注释掉的配置也要读**：鉴权 Filter 的 mapping 全被注释 = 形同虚设，只有逐行读配置才发现。
- 把「控制器包范围」和「AOP/过滤器切点范围」**叠起来看**，差集就是鉴权盲区。

产出：五张清单——后续覆盖矩阵的行列来源。

## P3 黑盒探测

详见 `blackbox-testing` skill。核心：把 P2 清单里的每类入口用**未授权**和**差分**各打一遍，得到「可达面地图」和「边界行为表」：

| 请求类型 | 未授权响应 | 结论 |
|---|---|---|
| 普通页面 | 302→login | 默认拒绝 |
| 白名单页 | 200 | 仅登录/验证码 |
| 控制器类 | 500 | 需会话（落应用 NPE） |
| 独立 Servlet | 200/405 | **过滤器盲区** |
| 静态资源 | 200/404 | 不鉴权 |

**这张表是整个审计的转折点**——一次性框定哪些洞今天能打、哪些需要账号、哪些被挡。

## P4 代码审计

详见 `code-audit` skill。核心：把 P2 的 Source/Sink 台账做**连线**，每类 Sink 用 `vuln-coverage` 清单的固定模式扫全库。字节码也是源码——**先反编译一切**（.class/.jar/.rar/.bak）。

## P5 黑白盒互证（核心）

把 P3（可达性）和 P4（代码缺陷）**叠加**，算真实可利用性并定级。对每个缺陷问三个问题：

```
① 入口线上可达吗？           → 查 P3 可达面地图
② 触发需要什么前置？         → 会话？密钥？特定参数？特定 Header？
③ 缺陷回显在这个容器成立吗？ → sendRedirect 后容器抑制响应体？异常被吞？
```

分级（**诚实比吓人重要**）：

- **未授权成立**：可达且无会话/密钥门
- **需会话**：代码确认，需登录
- **密钥门**：差一把钥匙（写明钥匙在哪、怎么会泄露、拿到后影响多大）
- **本实例被挡**：缺陷真，当前边界不可达（换实例可能成立）
- **代码缺陷**：未实机复现，诚实标注

典型组合判读：

- 缺陷真 × 实例 A 被 302 挡 × 实例 B 无过滤器 → A ⛔、B ✅。**同一缺陷因边界不同结论不同。**
- 可达 × IP 白名单信任 XFF（差分实测绕过）× 剩密钥门 → 「就差一把钥匙」。
- 污点链完整 × 需会话 × 本次无账号 → 🔒 诚实标注，不吹成「未授权可打」。

常见漏点：

- **把白盒结论直接当黑盒结论报**——报告写「未授权注入」，运维一测需要登录，信任崩塌。P5 就是防这个。
- 忘了容器语义：sendRedirect() 不终止页面执行，但容器抑制后续响应体——「读」类回显没了、「写」类副作用还在，不懂会误判回显型漏洞。

## P6 验证与利用链

用**最小、非破坏**的动作证明漏洞，并尝试**串链**放大影响。

1. **非破坏 PoC 优先级**：差分 > 时延 > 只读回显 >（授权且必要时）受控写探针。
   - 证 IP 绕过：看 `Illegal IP` → `Illegal param` 的响应差分，不需要真上传。
   - 证 SQLi：布尔差分 / 短时延，不拖库、不 --dump。
   - 证任意文件读：读 web.xml（无害），不读隐私数据。
2. **串链思维**：`硬编码 DB 口令 → 连库读 key → 满足上传 vkey → WebShell → RCE`。审计的价值往往在**链**，而不是单点。
3. **密钥/盲区评估**：卡在密钥时明确「钥匙在哪、怎么会泄露、拿到后影响多大」，交运维决策，而非擅自爆破。
4. **每个 PoC 留证据**：原始请求 + 原始响应 + 复现命令。

常见漏点：为「打穿」越过红线（**能证明即可，不必打穿**）；只报单点不串链（漏掉最有价值的攻击叙事）。

## P7 闭环与查漏（最后兜底）

系统性回答「**我还漏了什么？**」：

**覆盖矩阵自查**：入口 × 漏洞类型逐格标注，**任何一个格子空白（"没看过"）= 还没审完**。

**Completeness Critic 复查清单**：

- 有没有**没反编译**的 jar / .rar / .bak？
- 有没有**指纹提示存在、但没验证**的组件端点？
- 有没有**只在一个实例打、没在其他实例打**的？
- 有没有**污点源类型漏了**（只查 getParameter，漏了 getHeader/请求体/Cookie）？
- 有没有**假设当真、没验证**的结论？
- 有没有**把「代码缺陷但被挡」漏报**（它们是纵深防御依据）？

产出：覆盖矩阵（证明审全了）、分类报告（每条带证据带分级）、修复路线图（按「已验证 × 影响面」排序）。

## 工作纪律

1. 多实例穷举进台账，边界防护未必一致。
2. 指纹的价值是提醒「这类产品还有哪些标准攻击面」，源码没给也要线上验证。
3. 找到一个洞立刻做变体分析，抽象成模式再全库扫。
4. 单个原语受限时想串链。
5. 每条结论留证据；假设必须被验证，禁止臆断。
6. 阶段推进、探针结果、缺陷、覆盖格、点子全部写入 audit_workspace，不要只留在对话里。
