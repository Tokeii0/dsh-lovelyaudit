# 审计总体思路（P0–P7 螺旋）

## skill 路由（不确定用哪个时看这张表）

| 场景 | skill |
|---|---|
| 总流程、阶段节奏、互证定级、证伪 | `audit-methodology`（本篇） |
| 黑盒探测、指纹、可达性、WAF、边界绕过 | `blackbox-testing` |
| 白盒污点分析、取源反编译、配置与依赖 | `code-audit` |
| **确定了技术栈后的语言/框架专属陷阱** | `language-stack-audit` |
| 已知漏洞类型逐类扫 + 覆盖矩阵 | `vuln-coverage` |
| **认证/授权/会话/JWT/OAuth/多租户/越权** | `auth-authz-testing` |
| **API/GraphQL/WebSocket/CORS/云/容器/中间件/供应链/AI** | `modern-attack-surface` |
| 逻辑 0-day、假设破除、fuzz、竞态、变体分析 | `unknown-vuln` |
| **定级、报告要素、证据规范、修复建议、复测** | `audit-reporting` |
| 点子板、策略管理 | `audit-ideas` |
| 具体命令速查 | `audit-commands` |

先建威胁模型再动手：**谁会打**（未授权外部 / 低权限内部账号 / 中间人）、**想要什么**（数据 / 权限 / 立足点）、**系统最怕什么**（① 未授权 RCE：上传/反序列化 ② 未授权数据泄露：任意文件读/SQLi/越权 ③ 账号接管：认证绕过）。威胁模型决定所有动作的优先级——看到工资/病历模块，第一反应应是「泄露 = 全员数据曝光，优先级拉满」。

螺旋节奏，不是直线流水线：

```
P1指纹 → P2测绘 → P3黑盒摸底 → P4白盒深挖 → P5互证 → P6验证
       ↑ 发现新实例 / 新边界 / 新入口后回炉
P7 覆盖矩阵收口
```

审计不是一遍过的流水线，是「黑盒发现→白盒解释→黑盒验证→发现新面」的螺旋。每次互证都可能暴露新攻击面，回炉再审，直到覆盖矩阵没有空格才算闭环。

## P0 交战规则与目标确认

钉死「能做什么、不能做什么、打哪些目标」：

1. **确认授权范围**：哪些 IP/域名/端口在授权内。书面授权是前提。
2. **划红线**（尤其生产）：**以用户在 P0 填写的为准。用户没填，就不要自行发明默认只读禁令**——按授权范围正常探测与复现。下面这张分级表只是和用户确认红线时的对照模板：
   - 最低强度：只读探测、响应差分、时延、带外、字节码分析、读无害文件（web.xml 等配置）。
   - 中强度：任意文件**读**（节制隐私）、盲态探测（短 sleep）、受控并发、默认口令试一次。
   - 高强度：写/删数据、真传 WebShell、口令爆破、DoS、`--os-shell` / `--dump`。
   - 通用自律（与红线无关）：**能用差分/时延/带外证明的，就不必落地真实利用**——证明缺陷存在是目的，打穿不是。
3. **建目标台账**：不止一个 URL——把所有相关**端口和实例**列进来。**同一应用常有多个部署实例（主/移动/门户/测试/灾备），边界防护未必一致；一个实例打不通，换一个可能就通了。台账必须穷举所有实例。**
4. **敏感数据处置约定**：碰到真实 PII/凭据一律「证明即止」——证明能读，不读全量、不导出、不落盘；报告里脱敏。详见 `audit-reporting` R5。
5. **异常发现的上报通道**：约定好「发现下列情况立即停手并通知谁」。

**遇到这三种情况必须立即停止探测、保全证据、通知委托方，不要继续深入、不要清理痕迹、不要触碰疑似攻击者的文件：**

- **已存在的 WebShell / 后门 / 异常计划任务**（不是你传的）——说明系统可能**已被入侵**，你继续操作会污染取证现场，也可能被误认为是入侵者。
- **正在被利用的痕迹**（异常外连、可疑进程、被篡改的前端 JS）。
- **数据已经泄露的证据**（公网可访问的数据库备份、已被索引的敏感文件）。

**时间盒与优先级**：审计总是有限时的。按威胁模型排序推进——先打「未授权 RCE / 未授权数据泄露 / 账号接管」三条主线，再铺覆盖矩阵。**不要在低价值面上耗光时间**；每个阶段给自己一个时间上限，到点强制进入下一阶段，靠 P7 回炉补齐。

产出：目标/实例台账（用途、是否生产、边界防护线索）、红线清单、数据处置与上报约定。

## P1 信息收集与指纹

指纹越准，越能借力已知漏洞。

1. **HTTP 指纹**：Server、Set-Cookie 名、X-Powered-By、首页跳转、错误页特征、favicon hash。
2. **产品识别**：Cookie 名、路径特征、登录页版权、JS/CSS 路径 → 锁定产品。
3. **版本/构建时间**：文件时间戳、jar 版本、.class 编译信息、页面注释。
4. **已知 CVE 拉取**：确认产品后立刻把该产品线的公开漏洞拉进候选池，并列出该产品线的**标准攻击面端点**——**即使源码没给，也要主动去线上验证它们是否存在**。
5. **枚举实例**：配置、日志、页面里挖其他 IP/端口/域名。
6. **技术栈定型 → 挂对应语言 skill**：确定 PHP/Python/Node/Go/.NET/Ruby/Java 后，立刻按 `language-stack-audit` 对应 references 文件准备该栈专属锚点。**用错语言的 grep 模式 = 系统性漏报。**
7. **WAF / RASP / 防护设备识别**（决定后续所有探测的判读方式）：
   - 发一个必然恶意的探针（如 `?x=<script>alert(1)</script>` 或 `?id=1' or 1=1--`），看响应是**应用的**还是**设备的**。
   - 设备特征：固定拦截页/自定义 4xx、`Server`/Cookie 特征（安全狗、云锁、Cloudflare、ModSecurity）、响应极快（未到应用）、无论路径存在与否都同样拦。
   - 记录**拦截阈值**：哪些关键字触发、是拦请求还是只拦响应、是全局还是按路径。

> **WAF 是审计中假阴性的头号来源。** 不识别 WAF 就会把「被设备拦了」当成「这里没洞」。识别之后，所有后续探测都要在「WAF 语义」下判读，定级时也要写清「缺陷真实存在，当前被 WAF 拦截」而不是「无此漏洞」——WAF 规则一改、或换个未挂 WAF 的实例，就成立了。

常见漏点：只盯给的源码，不验证「应该存在但没给源码」的组件 → 漏掉产品级已知洞。指纹的价值就是提醒「这类产品还有哪些标准攻击面」。

产出：指纹表、产品/版本、技术栈、WAF/RASP 结论、已知 CVE 候选池、实例清单。

## P2 攻击面测绘（"不放过"的第一道兜底）

**把地图画完再打。** 五张清单，缺一不可：

1. **路由清单**：web.xml 每个 servlet-mapping / filter-mapping / welcome-file / error-page；框架注解路由全量提取（如 `grep -r "@RequestMapping"`）；URL 重写规则。
2. **JSP/页面清单**：全量枚举——每个都是潜在直连入口。
3. **内置/第三方组件端点**：编辑器（UEditor/FCKeditor）、报表、上传组件，各自带一堆端点。
4. **静态与残留**：.bak/.rar/.zip/.svn/.git/副本/test*——源码泄露与备份。
5. **Source/Sink 台账**：粗扫所有输入源和危险汇聚点建索引，为 P4 打底。

常见漏点：

- 只审业务大接口，漏边角：验证码 servlet、代理 servlet、include 片段、上传子组件——往往正是这些「不起眼」的地方无鉴权。
- **注释掉的配置也要读**：鉴权 Filter 的 mapping 全被注释 = 形同虚设，只有逐行读配置才发现。
- 把「控制器包范围」和「AOP/过滤器切点范围」**叠起来看**，差集就是鉴权盲区。

产出：五张清单——后续覆盖矩阵的行列来源。

## P3 黑盒探测

详见 `blackbox-testing` skill。核心：把 P2 清单里的每类入口用**未授权**和**差分**各打一遍，得到「可达面地图」和「边界行为表」：

| 请求类型 | 未授权响应 | 结论 |
|---|---|---|
| 普通页面 | 302→login | 默认拒绝 |
| 白名单页 | 200 | 仅登录/验证码 |
| 控制器类 | 500 | 需会话（落应用 NPE） |
| 独立 Servlet | 200/405 | **过滤器盲区** |
| 静态资源 | 200/404 | 不鉴权 |

**这张表是整个审计的转折点**——一次性框定哪些洞今天能打、哪些需要账号、哪些被挡。

四种待遇要分清（不是三种）：**拦 / 落应用 / 盲区 / WAF 拦**。前三种是应用与容器的行为，第四种是设备行为——把 WAF 拦截误读成「应用拒绝」会让整张表失真。

此外 P3 必须同时完成两件常被跳过的事：

- **角色矩阵**（有账号时）：不止「未授权 vs 授权」两态，要按 `auth-authz-testing` Z2 建 N 角色 × M 端点矩阵。
- **非 Web 端口不能只记录不测**：P1 扫出的 Redis/ES/Mongo/JMX/Dubbo 等端口逐个做无认证判定，见 `modern-attack-surface` M6。

## P4 代码审计

详见 `code-audit` skill；语言/框架专属陷阱见 `language-stack-audit`。核心：把 P2 的 Source/Sink 台账做**连线**，每类 Sink 用 `vuln-coverage` 清单的固定模式扫全库。字节码也是源码——**先反编译一切**（.class/.jar/.rar/.bak）。

## P5 黑白盒互证（核心）

把 P3（可达性）和 P4（代码缺陷）**叠加**，算真实可利用性并定级。对每个缺陷问三个问题：

```
① 入口线上可达吗？           → 查 P3 可达面地图
② 触发需要什么前置？         → 会话？密钥？特定参数？特定 Header？
③ 缺陷回显在这个容器成立吗？ → sendRedirect 后容器抑制响应体？异常被吞？
```

分级（**诚实比吓人重要**）：

- **未授权成立**：可达且无会话/密钥门
- **需会话**：代码确认，需登录。**必须同时写明「注册是否开放」**——开放注册的水平越权 ≈ 未授权数据泄露
- **密钥门**：差一把钥匙（写明钥匙在哪、怎么会泄露、拿到后影响多大）
- **本实例被挡**：缺陷真，当前边界不可达（换实例可能成立）。**被 WAF 拦也归此级，不是「无漏洞」**
- **代码缺陷**：未实机复现，诚实标注

### 证伪纪律（P5 的另一半，最易被跳过）

P5 不只要证明「成立」，更要**主动证明「不成立」**。每个疑似漏洞在标 verified 前，先尝试推翻它：

| 疑似现象 | 先排除的平凡解释 | 证伪动作 |
|---|---|---|
| 参数回显了 payload | 是不是**统一错误页/404 页**把 URL 原样回显？是不是在 `<!-- -->`/JSON 字符串里？ | 换一个不存在的路径打同样 payload，看表现是否一样 |
| 响应长度有差异 | 是不是**时间戳/随机 token/CSRF token** 造成的天然抖动？ | 同一请求重复 5 次，看基线波动 |
| 时延变长 | 是不是网络抖动 / 冷缓存 / 目标本身慢？ | 多次测量 + 对照组（无 payload 的同请求）取分布 |
| 换个 Header 就 200 了 | 是不是**任意** Header 都 200（根本没在校验）？ | 发一个随便编的 `X-Nonsense-Foo` 做对照 |
| 500 报错 | 是不是**任何**畸形输入都 500（只是没做输入校验，不等于注入）？ | 用无害畸形值（超长字符串）对照 |
| 探针被拦 | 是 WAF 还是应用拒绝？ | 看 P1 的 WAF 结论；用不触发规则的等价 payload 重试 |
| 疑似越权 | A 和 B 拿到的是不是**同一份公开数据**？ | 用 B 的会话取同一资源做对照，比对内容是否真属于 B |

**对照组是证伪的核心工具。** 没有对照组的单条响应，什么都证明不了。

**同样重要的反向纪律**：证伪失败不等于漏洞不存在——只说明当前方法没证到。该标 `code`（代码缺陷未复现）就标 `code`，不要因为没打通就删掉这条。

典型组合判读：

- 缺陷真 × 实例 A 被 302 挡 × 实例 B 无过滤器 → A ⛔、B ✅。**同一缺陷因边界不同结论不同。**
- 可达 × IP 白名单信任 XFF（差分实测绕过）× 剩密钥门 → 「就差一把钥匙」。
- 污点链完整 × 需会话 × 本次无账号 → 🔒 诚实标注，不吹成「未授权可打」。

常见漏点：

- **把白盒结论直接当黑盒结论报**——报告写「未授权注入」，运维一测需要登录，信任崩塌。P5 就是防这个。
- 忘了容器语义：sendRedirect() 不终止页面执行，但容器抑制后续响应体——「读」类回显没了、「写」类副作用还在，不懂会误判回显型漏洞。

## P6 验证与利用链

用**最小、非破坏**的动作证明漏洞，并尝试**串链**放大影响。

1. **非破坏 PoC 优先级**：差分 > 时延 > 只读回显 >（授权且必要时）受控写探针。
   - 证 IP 绕过：看 `Illegal IP` → `Illegal param` 的响应差分，不需要真上传。
   - 证 SQLi：布尔差分 / 短时延，不拖库、不 --dump。
   - 证任意文件读：读 web.xml（无害），不读隐私数据。
2. **串链思维**：`硬编码 DB 口令 → 连库读 key → 满足上传 vkey → WebShell → RCE`。审计的价值往往在**链**，而不是单点。
3. **密钥/盲区评估**：卡在密钥时明确「钥匙在哪、怎么会泄露、拿到后影响多大」，交运维决策，而非擅自爆破。
4. **每个 PoC 留证据**：原始请求 + 原始响应 + 复现命令。

常见漏点：为「打穿」越过红线（**能证明即可，不必打穿**）；只报单点不串链（漏掉最有价值的攻击叙事）。

## P7 闭环与查漏（最后兜底）

系统性回答「**我还漏了什么？**」：

**覆盖矩阵自查**：入口 × 漏洞类型逐格标注，**任何一个格子空白（"没看过"）= 还没审完**。

### 矩阵外必查项（矩阵是「入口 × 类型」，这些不属于单个入口）

矩阵 14 列（RCE/SQLi/文件/SSRF/XXE/XSS/越权/认证/CSRF/重定向/密码学/并发/信息/逻辑）逐格填完之后，**下面这些面仍然一格都不占**——不在列里，就永远不会因为「有空格」被发现漏掉。所以单列一张必查表（完整版见 `vuln-coverage` §H）：

- [ ] **多租户隔离**（SaaS 必查）与 **BFLA 函数级越权**（裸奔方法清单）→ `auth-authz-testing`
- [ ] **密码重置链与账号接管路径**；**JWT/OAuth/SAML** 逐条（若使用）
- [ ] **CORS / WebSocket / postMessage / 原型链污染 / 点击劫持** → `modern-attack-surface` M1 M2
- [ ] **HTTP 协议层**：Host 头、缓存投毒/欺骗、请求走私、CRLF → M3
- [ ] **Mass Assignment / HPP / 字段过度暴露 / 批量端点**
- [ ] **解压与解析器**（Zip Slip、ImageMagick、ffmpeg、Office/PDF）；**JNDI 与日志注入**
- [ ] **残留与源码泄露**：`.git`/`.env`/`.map`/备份包/heapdump/前端 bundle 里的密钥
- [ ] **依赖与组件 CVE**（分「链路已确认」与「存在即风险」）+ **供应链 / CI-CD** → M7
- [ ] **配置基线**：框架主密钥、调试模式、管理端点（actuator/druid/swagger/console）、安全响应头、目录列表、上传目录可解析脚本
- [ ] **非 HTTP 服务与云面**：Redis/ES/Mongo/JMX/Dubbo、云元数据、对象存储 → M4 M6
- [ ] **限速与资源耗尽**；**AI/LLM 功能面** → M8（目标含大模型时）
- [ ] **每个技术栈都按 `language-stack-audit` 对应 references 文件扫过**（多语言项目逐栈，别只用一套语言的 grep）

**Completeness Critic 复查清单**：

- 有没有**没反编译**的 jar / .rar / .bak？
- 有没有**指纹提示存在、但没验证**的组件端点？
- 有没有**只在一个实例打、没在其他实例打**的？
- 有没有**污点源类型漏了**（只查 getParameter，漏了 getHeader/请求体/Cookie/二次污点）？
- 有没有**某个技术栈没按 `language-stack-audit` 对应 references 文件过**（多语言项目里的老 PHP 模块、前端、native 组件）？
- 有没有**假设当真、没验证**的结论？
- 有没有**把「代码缺陷但被挡」漏报**（它们是纵深防御依据）？
- 有没有**只报单点、没做变体分析**（同模式的兄弟位置）？
- 有没有**只报现象、没提根因**（5 条漏洞其实是同一个配置错误）？
- 有没有**把 WAF 拦截当成「没漏洞」**？

产出：覆盖矩阵（证明审全了）+ 矩阵外必查表、分类报告（每条带证据带分级）、修复路线图（按「已验证 × 影响面」排序）。**交付物的格式、定级、证据、修复建议、复测规范见 `audit-reporting`。**

## 工作纪律

1. 多实例穷举进台账，边界防护未必一致。
2. 指纹的价值是提醒「这类产品还有哪些标准攻击面」，源码没给也要线上验证。
3. 找到一个洞立刻做变体分析，抽象成模式再全库扫。
