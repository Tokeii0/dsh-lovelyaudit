# 未知漏洞（0-day / 未公开）挖掘方法

已知类型靠清单兜底；真正的「不放过任何一个」难在**未知漏洞**——没有 CVE、没有固定模式、SAST 扫不出、字典跑不到。未知漏洞的本质不是技术特例，而是一种**思维方式**。

## 核心命题：一切安全控制都建立在「假设」之上，未知漏洞 = 打破那个假设

开发者写每段安全代码时，脑子里都有一串**隐含假设**：

> 「这个 IP 是真实来源」·「这个 id 是他自己的」·「这两步会按顺序走」·「这个值来自我们内部」·「用户不会传负数」·「这个 token 只有服务端能生成」·「这个文件名不会有 ../」·「同一个请求不会并发到两次」……

**每一个假设，都是一个攻击点。** 本质动作：

```
① 识别系统在每个信任边界上做了什么【假设】
② 逐个问：「如果这个假设不成立会怎样？」
③ 构造让假设失效的输入/时序/状态
```

## 技术一：信任边界测绘（最高产的 0-day 来源）

画出每处「从不可信侧进入可信侧」的边界，检查信任是否被滥用。

| 系统信任了什么 | 为什么错 | 如何打破 |
|---|---|---|
| X-Forwarded-For/X-Real-IP 是真实 IP | 客户端可伪造 | 伪造内网 IP 绕过白名单 |
| 客户端传的 userId/role/orgId 是身份 | 身份应来自会话 | 改参数越权 |
| 某内部服务/回调是可信的 | 可被 SSRF/伪造触达 | 伪造内部调用 |
| 前端已做校验 | 前端可绕 | 直接打后端 |
| 签名/token 可信 | 密钥可能为空/硬编码/可推导 | 离线伪造 |
| Referer/Origin 代表来源 | 可伪造/可空 | 伪造 |
| 文件扩展名代表类型 | 可改 | 双扩展/内容不符 |

方法：白盒 grep 所有读 Header/身份/权限的地方（getHeader / getRemoteAddr / getAttribute("role") / getParameter("uid")），逐个问「这个值可信吗？被谁用来做安全决策？」；黑盒对每个「内网限制/身份/权限」点用差分测它信不信客户端可控的值。

## 技术二：业务逻辑与状态机分析

模式扫描永远扫不出逻辑漏洞——它们「语法正确、语义错误」。方法：**重建预期流程，然后攻击每一个环节假设**。

1. **画状态机/流程图**：把业务流程（下单、支付、审批、改密、提现）的每一步、每个状态、每次校验画出来。
2. **对每一步问反事实问题**：
   - **跳步**：能不能跳过第 2 步直接到第 3 步？（跳过支付直接发货）
   - **重放**：某步能不能重放多次？（重复领券、重复退款）
   - **越权**：这一步的操作对象能不能换成别人的？
   - **边界值**：数量填 0/负数/超大？金额填负数（负负得正=充值）？
   - **并发**：两个请求同时到会怎样？
   - **顺序**：打乱步骤顺序？先审批后修改内容？
   - **状态混淆**：用 A 状态的 token 去操作 B 状态的资源？
3. **校验一致性**：前端校验/后端校验/数据库约束是否一致？只有前端校验 = 直接打后端。

高频逻辑漏洞清单（逐条对照业务）：

- 支付：改价、改数量、改币种、四舍五入套利、重复回调、订单状态未校验
- 优惠：叠加不该叠加的券、负数、重复使用、并发领取
- 账号：越权改他人资料/密码、密码重置 token 可预测/可越权、绑定劫持
- 审批/工作流：跳节点、越权审批、修改已提交内容、伪造流转
- 提现/积分：负数、并发、精度、重复

**心法：开发者测的是「正常人怎么用」，你要测「坏人怎么用」。每一条业务规则都是一个待打破的假设。**

## 技术三：差分分析

用「两个本应相同/不同的东西之间的差异」暴露漏洞：

- **版本/补丁差分（挖 1-day 与变体）**：拿到新旧两版 diff 出补丁 → 反推被修漏洞 → 在未打补丁目标上利用。工具：BinDiff/Diaphora、git log/源码 diff、jar 反编译后 diff。补丁往往只修一处，同样错误模式别处可能还在。
- **行为差分**：同操作不同输入 → 不同响应（长度/时延/状态码/报错），暴露注入/盲态/条件分支；**不同实例 → 不同行为**，同源码不同边界，差分暴露软肋实例；不同账号/角色 → 相同资源，越权。
- **实现差分**：前端校验 vs 后端校验；不同解析器对同一输入的理解差异（HTTP 请求走私、Content-Type 混淆、XML/JSON 解析歧义）；代理与后端对 URL/路径的理解差异 → 鉴权绕过。

## 技术四：Fuzzing

- **输入层**：参数灌畸形值（超长、特殊字符、类型混淆 array/obj、编码变体、边界数字），看异常/500/时延/回显；未知参数挖掘（param-miner/Arjun）；内容类型/结构 fuzz（JSON→XML、多部分边界畸形、嵌套深度、重复键）。
- **协议/解析层**：HTTP 请求走私（CL.TE/TE.CL）、头注入、畸形分块、文件格式 fuzz（上传解析、图片/文档解析器）。
- **代码层**（有源码/二进制）：覆盖引导 fuzz——AFL++/libFuzzer（native）、Jazzer（JVM）、go-fuzz、Atheris（Python）。给每个**解析器/反序列化器/协议处理**写 harness。崩溃 → 分析可利用性。
- **语法感知**：对结构化输入（SQL/XML/表达式/模板）用语法模板生成，比纯随机高效。

Fuzzing 系统性探索「人想不到的输入空间」，是发现未知崩溃与解析歧义的主力。

## 技术五：并发 / 竞态 / TOCTOU

单线程视角看不出的漏洞，并发下暴露。**任何「检查后使用」都可疑。**

- 白盒：grep「先查后改/先判后用」——查余额→扣款、查库存→下单、判重复→插入、查权限→操作。中间无锁/无事务/无原子操作 = 竞态。
- 黑盒：对「每人限一次/余额校验/状态校验」接口**并发发 N 个相同请求**：

```bash
seq 20 | xargs -P20 -I{} curl -s -b "SESSION=x" -X POST "http://TARGET/claim-coupon"
```

利用：超发（券/积分/库存）、双花、绕过限次、状态竞争。工具：Turbo Intruder、自写多线程。

## 技术六：Gadget 链 / 利用原语构造

拿到「半成品」漏洞（可控反序列化点、可控文件写、内存破坏）后，下半场是**变成可用利用**：

- **反序列化 Gadget 挖掘**：目标 classpath 里有哪些类可串成执行链？搜**该应用特有的新 gadget**（不止现成工具）。
- **原语升级**：任意文件写 → 写哪（webshell 目录/计划任务/配置/SSH key）；任意文件读 → 读什么最值（密钥→更多权限）；SSRF → 打哪个内网服务（元数据/Redis/内部 API）。
- **信息 → 密钥 → 通道**：硬编码口令 → 读 key → 过上传门 → WebShell。**单个原语受限，串成链就是 RCE。**

## 技术七：变体分析（「找到一个，就找出全部」）

**这是「不放过任何一个」的关键放大器。** 找到一个漏洞后**不要停**——它几乎从不孤立：

1. 把漏洞**抽象成一个模式**（如「校验了 filename 却漏了另一个路径参数」）。
2. 用这个模式**全库再扫一遍**，找所有同类兄弟。
3. 用 CodeQL/Semgrep 写成规则，一次抓全变体。

**开发者的错误会复制粘贴，漏洞也会。找到一个 anti-pattern，用它当探针扫全项目——这是从 1 个到全部的杠杆。**

## 技术八：攻击者视角的资产/入口再枚举

未知漏洞常藏在「没人审的地方」：

- **隐藏/废弃端点**：test.jsp、debug、/actuator、老接口、注释里的 URL、JS 里未启用的调用。
- **后门排查**：非常规文件、可疑时间戳、异常鉴权短路（`if(pass=="magic")`）、硬编码万能参数/口令。
- **内部服务**：页面泄露的本机无鉴权端口（SSO 等），往往是横向跳板。

## 把八种技术编织进流程

未知漏洞挖掘不是独立阶段，而是**贯穿 P3–P6 的思维叠加**：

```
测绘每个入口时    → 同时画它的【信任边界】和【业务假设】（技术一、二）
读每段安全代码时  → 问「这个假设能否打破」（技术一）
每个响应差异      → 追差分根因（技术三）
每个解析器/输入点 → 上 Fuzz（技术四）
每个「检查后使用」→ 试并发（技术五）
找到任何一个洞    → 立刻做变体分析扫全库（技术七）
拿到任何原语      → 想怎么串成链（技术六）
收尾              → 攻击者视角再枚举隐藏面/后门（技术八）
```

## 心法总结

| 已知漏洞思维 | 未知漏洞思维 |
|---|---|
| 「这里符合某漏洞模式吗？」 | 「开发者在这里**假设**了什么？能打破吗？」 |
| 扫模式、匹配 CVE | 建威胁模型、破假设、差分、fuzz |
| 找到即止 | 找到一个 → 变体分析找全部 |
| 单点报告 | 串链放大 |
| 靠工具广度 | 靠**逆向开发者意图**的深度 |

**已知漏洞靠「记忆与匹配」，未知漏洞靠「重建开发者的心智模型，然后逐条推翻它」。**

找到的假设、变体、链条全部写入 audit_workspace（点子板 / findings）。
