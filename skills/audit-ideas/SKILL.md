# Ideas（解题点子系统）

Ideas 是运行时策略管理：辅助模型自动提炼「可以尝试的方向」，追踪每个方向的验证状态，形成一张**活的策略地图**。

| | Skill（技能） | Ideas（点子） |
|---|---|---|
| 本质 | 赛前知识库 | 赛中策略图 |
| 时间 | 静态、预先编写 | 动态、运行时生成 |
| 粒度 | 通用技术指南 | 针对当前目标的具体假设 |
| 生命周期 | 跨题目持久 | 绑定单个会话/目标 |

**Skill 是教科书，Ideas 是草稿纸。**

## 1. 点子是假设，不是记录

点子回答「接下来可以试什么方向？」，不是「刚才做了什么」。

```
✅ 好点子的样子：
  - 尝试对 /api/login 的 username 做 SQL 注入
  - 检查 JWT token 的签名算法是否为 none
  - 测试文件上传是否允许 .php 后缀
  - 假设 X-Forwarded-For 被 IP 白名单信任，伪造 127.0.0.1 差分验证

❌ 这些不是点子：
  - 发现 8080 端口开放    → 这是观察
  - 成功读取 /etc/passwd  → 这是结果
  - 下载了挑战文件        → 这是任务
```

未知漏洞向的好点子还应包含：**要打破的假设 + 具体入口/参数/状态 + 对照请求 + 预期差异 + 停止条件**。

**点子模板**（照着填，写不出来说明这条还没想清楚，先别建）：

```
假设：      服务端假设 X-Forwarded-For 是真实来源 IP
入口：      POST /InternalServlet
动作：      带 X-Forwarded-For: 127.0.0.1 发一次
对照：      不带该头发一次（其余完全相同）
预期差异：  响应从 "Illegal IP" 变为 "Illegal param" → 说明过了 IP 校验
成本：      1 个请求
停止条件：  两次响应完全一致 → 该头不被信任，改测 X-Real-IP / Proxy-Client-IP
```

**对照请求是必填项。** 没有对照组的点子，验证出来的结论也没法证伪（见 `audit-methodology` P5 证伪纪律）。

## 2. 状态驱动的策略演化

```
pending（待验证）→ testing（验证中）→ verified（有效）/ failed（无效）/ skipped（跳过）
```

**关键理念：失败的点子和成功的一样有价值。** 一个标了 failed 并带失败原因的点子，直接防止后续轮次重复尝试同一方向——这在长跑（100+ 轮）中极其关键。

## 3. 使用纪律

- 先读 Skill 拿通用方法论，再把针对当前目标的具体假设写进点子板，验证后更新状态。
- 一轮只打一条：做完立刻 update_idea 写结果或失败原因，再换下一条。
- 优先 high 优先级、低成本的点子；尊重 skipped，不要再试。
- 同一个假设不要换措辞重复建点子。
- 点子只属本会话，不跨会话复用。

## 4. 点子来源、演化与复盘

### 点子从哪来（没思路时按这四个源头生成）

1. **覆盖矩阵的空格**：每一个 `unseen` 格子直接变成一条点子（"入口 A × SSRF 还没查"）。**矩阵驱动能保证不漏，是最可靠的点子源。**
2. **矩阵外必查清单**（`vuln-coverage` §H）：认证/CORS/协议层/竞态等不在矩阵列里的面，逐项建点子。
3. **已验证漏洞的变体**：找到一个洞立刻建一条"用同一模式全库再扫"的点子（`unknown-vuln` 技术七）。
4. **失败点子的邻居**：`失败` 不等于死路——`SQL 注入在 /login 被 WAF 拦` → 新点子 `换 multipart 传参 / 换盲态无关键字差分`。

### 演化与复盘

- 点子会演化：「SQL 注入在 /login 失败（有 WAF）」→ 新点子「尝试 Unicode 编码绕 WAF」。
- 复盘价值：哪类方向花了太多轮才放弃、制胜路径是什么——这些反馈沉淀为更好的优先级判断。
- 人机协作：用户可在「黑盒/代审」页添加点子、标优先级、否决（skipped）。人类提供直觉和创意，Agent 提供执行力和耐心。
